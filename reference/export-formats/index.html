Export formats

A finished board can leave the tool in several forms. Because the board is an event log, everything below except the log itself is regenerable from it at any time.

Board file (.board.json)

Section titled “Board file (.board.json)”

The canonical deliverable and the only artifact you truly need to keep. It is the full event log: every action, actor, timestamp, and per-sticky change history. It re-imports anywhere with history intact. Facilitator export.

Spreadsheet workbook (.xlsx)

Section titled “Spreadsheet workbook (.xlsx)”

The structured workbook that replaces hand transcription. Up to eleven sheets: Workshop overview, Events, Commands, Actors, Policies, Aggregates and Systems, Contexts, Relationships, Hotspots and Decisions, Build plan, and Glossary (the Glossary sheet appears only when the workshop has terms). Available to everyone.

Event Portal import file (.ep.json, format 2.0.0)

Section titled “Event Portal import file (.ep.json, format 2.0.0)”

A downloadable import file in the same shape Event Portal’s own Application Domains export produces. You import it through Event Portal’s UI rather than the tool pushing to a live tenant, so there are no runtime credentials, you can inspect exactly what you hand a customer, and a failed import is harmless. Facilitator export.

The mapping:

Board elementEvent Portal element
Context boundary (or any sticky’s context attribute)Application domain
External system (via system attributes)Application, homed in the domain where the majority of its stickies live
Domain eventEvent, with a resolved topic and a schema (or a “schema TBD” marker)
An event’s emitter system attributePublish relation (that application produces the event)
An event → policy link + the policy’s systemSubscribe relation (that application consumes the event)

Two principles govern the mapping: relationships come from attributes and accepted links (publish from an event’s emitter system, subscribe from event → policy links) and never from where stickies sit, and nothing is mandatory (schema-less events export with a “schema TBD” marker, and missing attributes downgrade an element or skip a relation with a warning rather than failing the export). See Mapping to Event Portal for the reasoning behind the mapping.

Two details you will notice in the imported result:

  • A workshop group tag. Every application domain name arrives prefixed with a three-letter tag derived from the workshop name (“Sunrise Hotel” gives SHU: Booking), so one workshop’s domains stay grouped and recognizable inside a shared Event Portal tenant.
  • Schema sketches are normalized. Free-form sketches are coerced into valid JSON Schema on the way out, so the import never fails on a sketch typed in a hurry.
  • Everything arrives as draft. Domains, applications, and events import in a draft state, a faithful starting point your architects review and promote inside Event Portal. See Mapping to Event Portal.

Event architecture diagram (.svg)

Section titled “Event architecture diagram (.svg)”

The Event Portal graph view of the model: a node-link picture where each application is a dashed ring, each event a solid dot, and each domain a grouping bound holding its nodes. Applications sit as hubs of the events they touch (a force-directed layout). Arrows follow Event Portal’s convention: an arrow into an event means an application publishes it; an arrow into an application means it consumes the event. Direction alone carries the meaning, so there is one arrow style. Drawn from the same plan as the .ep.json, so the picture and the import file cannot disagree. Facilitator export.

Board Review CSV

Section titled “Board Review CSV”

The Board Review register (both the static and AI findings, with your triage decisions) as a CSV for offline tracking.

SVG snapshot

Section titled “SVG snapshot”

The board as a standalone vector image, the digital equivalent of the wall photo - two flavors: the current view (whatever arrangement you are looking at, lane furniture included) and the workshop picture (all views stacked into one document). Both honor the wall theme, grid, and sticky font you have set.

Session replay

Section titled “Session replay”

Not a file, but worth listing: the log replayed at adjustable speed with time-travel, the “watch the model emerge” view, captioned with who did what. See Replay and history.

Workshop synthesis (AI, optional)

Section titled “Workshop synthesis (AI, optional)”

When an AI provider is configured, the tool can generate a workshop synthesis: a summary, a decision log, and a hotspot register. It degrades to absent with no provider configured and is never on the critical path. See AI assist.

Availability

Section titled “Availability”

Exports and replay work throughout an active board and keep working through finalize and archive (permanent, read-only), so the deliverables survive the room closing. Some are facilitator-only, as the labels above note; the rest are available to everyone.
