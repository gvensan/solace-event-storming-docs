Timers and timeboxes

Event Storming is a timeboxed method: you give the room a fixed window per activity (“15 minutes, put up every event you can think of, go”) to force divergence before convergence. The phase timer is the shared, digital version of that stopwatch. It is a single countdown computed identically on every screen, so a distributed room sees the same clock. It is a facilitation cue, never an enforcer.

Who operates it

Section titled “Who operates it”

Facilitator only. Setting, extending, or clearing a timer rides on the phase change. Participants and observers see the countdown but cannot change it.

Using it

Section titled “Using it”
  • Set a timer by entering minutes when you switch phase. Per-phase defaults pre-fill sensible values (out of the box: 30, 20, 75, 50, and 30 minutes, sized to a four-hour workshop; change them in Settings, Board, phase timeboxes).
  • Run it like a transport: play ▶ starts the clock, pause ⏸ stops it while remembering the remainder, resume picks it back up, stop ⏹ clears it, and restart ↻ runs the same timebox again.
  • Extend a running timer with “+5 min”.
  • The countdown shows as an mm:ss chip for everyone. On expiry it turns red and counts negative.
  • Clear it by changing phase without a value (or with stop).

There is one active timer per board, tied to the current phase, and it is optional: a phase can run with no timer.

On expiry

Section titled “On expiry”

Hitting zero fires a banner (“timebox up, ready to converge?”) and a one-shot chime. That is all it does. It never auto-advances the phase or locks the board. The timer prompts the human facilitator; it does not act.

Retrospective

Section titled “Retrospective”

Because the timer lives in the event log, playback can show planned-versus-actual duration per phase, a useful “where did the time go” view at the end. See Replay and history.
